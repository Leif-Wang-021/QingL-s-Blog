# 博客写作与更新规范

适用于 QingL 博客的公开文章。保留个人经历和学习过程，用清晰的技术笔记语言表达；理论、推测、实验结果分开写。

## 分类、系列与标签

| 分类 | 内容 | 现有系列 |
| --- | --- | --- |
| 学习笔记 | 概念梳理、教程与基础实践 | 深度学习入门 |
| 文献阅读 | 论文方法、个人理解与复现实验 | 无线通信文献 |
| 硬件项目 | 需求、设计、制作、测量与迭代 | STM32 音频系统、数字化 COS 头套 |
| 软件项目 | 应用介绍、移植、使用与版本记录 | Venera、wild 鸿蒙版 |

每篇只有一个分类。`series` 用稳定的主题或项目名，`seriesOrder` 为系列内唯一的正整数。系列页和文内目录自动生成；新增文章只填元数据，不手写整套导航。文献系列的编号仅表示整理顺序，标题无需加序号。

每篇使用 2–5 个标签，选领域、核心技术和工具。统一写法：无线通信、通信 AI、WMMSE、波束成形、深度学习、Tensor、PyTorch、STM32、PWM、HarmonyOS、VS Code。分类和标签各有职责，不以完整项目标题作为分类。

## 命名与目录

- 连续教程、硬件过程：`系列名（01）：具体主题`，后续为 02、03……。
- 文献：`方法或主题 阅读笔记：研究问题或学习重点`；完整论文名、作者和出处放正文。
- 软件总览：`项目名：定位与主要功能`；版本号放正文，后续版本记录可用 `项目名 v版本：主要变化`。
- 标题说明内容，避免只写“Hi”“开始”“P1”或一长串论文译名。
- 新文章用简短、稳定的目录名，例如 `learning/deep-learning/training-loop/index.md`；图片放在同一目录。
- 已发布文章保留原目录及 URL。只调整显示标题，减少旧收藏和站外链接失效。

## 正文语言与结构

正文标题从 `##` 开始，子标题依次为 `###`、`####`。文章标题由页面显示。摘要用一两句说明主题、范围和读者能获得什么，避免每篇都以“本文记录”开头。

保留第一人称、真实经历和少量个人语气；减少重复免责声明、无依据的“完美、必然、全面验证”和空泛总结。中文与英文术语保持自然间隔，单位写作 `35–45 kHz`、`1 ms`；代码中的标识符不改写。

| 类型 | 正文建议 |
| --- | --- |
| 学习笔记 | 背景 → 概念 → 示例 → 易错点与小结 → 来源 |
| 文献阅读 | 完整引用与阅读目标 → 问题 → 方法 → 个人理解 → 复现实验 → 局限 |
| 硬件项目 | 目标与阶段 → 方案和参数 → 实现 → 测量 → 待解决问题 |
| 软件项目 | 来源与定位 → 功能 → 界面 → 下载与安装 → 限制与反馈 |

结构按内容裁剪，不为凑栏目添加空段落。已有公式、代码、实验数据和来源保留；技术纠错另作明确说明。未测量的指标写“目标/待验证”，学习示例不能写成已经完成完整论文复现。

## 创建与发布

在博客目录运行，例如：

```powershell
pnpm new-post learning/deep-learning/training-loop --type learning --title "深度学习入门（04）：训练与验证循环" --series "深度学习入门" --order 4
```

`--type` 可选 `learning`、`paper`、`hardware`、`software`。新建文章默认为草稿；`--dry-run` 只预览模板。完成摘要、标签、正文和图片后，将 `draft` 改成 `false`，并把 `published` 改为实际发布日期。

```powershell
pnpm content:check
pnpm check
pnpm build
pnpm preview
```

依次运行检查和构建，避免 Windows 下多个 Astro 进程同时写缓存。确认正文、图片、系列链接后再提交并推送 `main`；GitHub Pages 工作流负责部署。

## 持续更新

`published` 始终保留首次发布日期；修改正文、配置或结论时，将 `updated` 改为实际更新日期。更新过的文章会显示更新时间，并在结构化数据中记录修改日期。

小修直接修改原文；重要改动在文末追加“更新记录”，例如 `2026-10-07：补充鸿蒙平板截图与安装限制`。新阶段、新实验或有独立价值的版本变化新建系列文章，不把所有内容堆入总览。

教程记录适用系统、工具版本与实际验证情况；软件总览提供稳定的仓库/最新版本入口，同时注明正文对应版本日期；文献笔记区分原文结论、个人解释与实验状态。旧的物料清单、预算、计划在更新前确认，不能把早期设想自动改写为当前进展。
